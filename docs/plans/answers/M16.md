# M16 answers — Frontend slice

1. **Server data in a global store.** It duplicates the server's source of truth in a client cache you must hand-manage: staleness, refetching, invalidation, loading/error states, deduplication, retries and garbage collection all become your code. Server-state libraries (TanStack Query) solve exactly this with cache keys and invalidation. Global stores fit genuine client state (UI preferences, wizard state).
2. **PKCE SPA vs BFF.** PKCE in the SPA: simple architecture, but access tokens live in the browser (JS memory/storage), so any XSS can steal or use them, and refresh tokens in the browser are risky. BFF: the server holds the tokens and the browser gets an HttpOnly, SameSite cookie, so tokens are never exposed to JS and the attack surface is smaller. Costs: a server component to run, CSRF protection needed, and sticky concerns for SignalR/websocket auth. Current guidance (OAuth for browser-based apps) favours BFF for sensitive apps.
3. **412 and 409 in the client.** 412 (stale ETag): tell the user the data changed since they loaded it, refetch the latest, and let them reapply their change (or merge if trivial); roll back any optimistic update. 409 (business conflict, e.g. illegal transition): show the ProblemDetails message mapped from `type`, roll back the optimistic update, refresh the affected data. Never retry blindly.
4. **URL state.** Shareable links and bookmarks, browser back/forward behaving correctly, reload restoring the exact view, deep links from notifications or other systems, and easy support ("send me the URL"). It's the single source of truth for navigation state.
5. **After reconnect.** Re-establish the connection (with backoff), re-authenticate if needed, re-join groups/subscriptions (server-side groups are lost on a new connection), backfill missed updates (fetch the current state/last positions since the last received timestamp), dedupe/order by event time, and show the user a connection/freshness indicator meanwhile.
6. **useEffect fetch.** No error handling (a non-2xx or network error is ignored; `r.json()` of an error page may throw), no loading state, no cancellation/abort on unmount (state updates after unmount, race conditions when deps change), no caching/deduplication/retries, no auth header or ProblemDetails handling, and untyped data. Use the generated client + TanStack Query.
7. **Generated client.** Types and endpoints stay in sync with the OpenAPI contract, so breaking API changes become compile errors instead of runtime bugs. Less boilerplate, consistent error handling and serialisation, and it enforces contract-first discipline.
8. **Component vs E2E.** Component tests verify a component's behaviour in isolation (rendering, interactions, edge states) with mocked APIs (MSW): fast and many. E2E tests verify that a real user journey works across the whole system (browser → gateway → services → DB → push): slow and few, but they're the only proof that the integrated system works.
9. **React vs Blazor.** React: the largest ecosystem and talent pool, mature tooling and component libraries, best for rich and highly interactive UIs; a second language/toolchain in a .NET shop. Blazor: one language (C#) and shared models/validation with the backend, faster for .NET teams, good for internal line-of-business apps; a smaller ecosystem, WASM download size or server-mode connection costs, fewer frontend specialists. Choose by team skills, app type and hiring.
10. **Dispatcher console.** A SPA with route-level code splitting; server state via TanStack Query with real-time updates pushed through SignalR that update/invalidate query caches; a multi-window/multi-monitor approach (separate routes per window, synchronising selection via BroadcastChannel); virtualised lists and map clustering for performance over 8-hour sessions (watch for memory leaks: unsubscribe and cap the trail length); keyboard shortcuts and accessibility; resilient reconnect + freshness indicators; optimistic actions with conflict handling; error boundaries and client telemetry correlated with backend traces.
