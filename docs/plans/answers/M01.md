# M01 answers — Modern C# & runtime essentials

1. **async state machine.** The compiler rewrites the method into a struct state machine with `MoveNext()`. At an `await` on an incomplete task, it stores the state (locals and position), registers a continuation on the awaiter, and *returns* to the caller (the thread is freed). When the task completes, the continuation calls `MoveNext()` again, possibly on another thread, which resumes after the `await`. If the task is already complete, execution continues synchronously.
2. **.Result in ASP.NET Core.** No deadlock from a SynchronizationContext, but it **blocks a thread-pool thread** while waiting. Under load many requests block threads at once, the pool runs out of threads, and new work (including the completions those blocked threads are waiting for) queues up. That's **thread-pool starvation**. The pool injects threads slowly (~1–2/s past the minimum), so latency explodes while CPU stays low.
3. **ValueTask.** Use it when the result is often available synchronously (cache hits, buffered reads) on hot paths, to avoid allocating a `Task`. Rules: await it **once**, never await it concurrently, don't call `.Result` before it completes; call `.AsTask()` if you need any of that. The default should still be `Task`.
4. **GC generations.** Gen0 holds new short-lived objects, collected often and cheaply. Gen2 holds long-lived objects, and collections there are expensive (full GC). The LOH holds objects ≥ 85,000 bytes; it's collected only with Gen2 and isn't compacted by default, so it fragments. A 90 KB array goes straight to the LOH: frequent allocation causes Gen2 collections and fragmentation, whereas many small short-lived arrays die cheaply in Gen0. (Use `ArrayPool<T>` for big buffers.)
5. **Span restrictions.** `Span<T>` is a `ref struct`: it can point to stack memory (`stackalloc`) or the interior of arrays, so it must live only on the stack. Storing it in a heap object (a class field) or across an `await` (the state machine is on the heap) could let it outlive the memory it points to. Use `Memory<T>` for those cases.
6. **Captive dependency.** `AddDbContext` registers scoped; the singleton captures one `AppDb` instance forever. Symptoms: a `DbContext` used concurrently from multiple requests ("A second operation was started on this context…"), a change tracker growing without bound (memory leak), stale data, and connection problems. Fix: make `ReportService` scoped, or inject `IServiceScopeFactory`/`IDbContextFactory<AppDb>` and create a scope per operation. `ValidateScopes` catches it at startup in Development.
7. **async void.** (1) Exceptions can't be caught by the caller and are raised on the SynchronizationContext/thread pool, which can **crash the process**. (2) The caller can't await completion, so there's no backpressure, ordering or knowledge of when it finished (and tests can't wait for it). Return `Task` instead. `async void` is only for event handlers.
8. **WhenAll over 10k calls.** It starts all 10k at once: socket/connection exhaustion, rate limits on the remote side, memory spikes, and timeouts cascade. Bound concurrency with `Parallel.ForEachAsync(items, new ParallelOptions { MaxDegreeOfParallelism = 20 }, ...)`, a `SemaphoreSlim`, or a Channel with N workers, plus resilience and cancellation.
9. **IAsyncEnumerable.** It streams results as they're produced: the server doesn't buffer the whole list in memory, and the client can start receiving early (ASP.NET Core streams the JSON array). Cancellation is honoured mid-stream. It's good for large exports. Trade-off: once streaming has started you can't change the status code.
10. **p99 spikes with low CPU.** (a) GC pauses (Gen2/LOH): `dotnet-counters` (GC heap size, % time in GC, Gen2 count) or `dotnet-trace` GC events. (b) Thread-pool starvation from sync-over-async: `dotnet-counters` thread-pool queue length/thread count, or `dotnet-stack`. (c) Connection pool exhaustion or lock contention (DB pool, `lock`): Npgsql metrics/`pg_stat_activity`, the contention counter (`monitor-lock-contention-count`). Also check timers and cache expiry storms.
